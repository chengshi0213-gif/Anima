# v1.2.1 规划 — Codex 对标：安全 · 双轨 · 全场景

> **核心目标**：用户用 Codex 能做的事，用 Anima 都能做，效果不差。
> 照顾两类用户：**国内（不翻墙）** 和 **国际**，每个能力类别都有对应方案。
>
> 版本：`1.2.1`　　分支：`feat/v1.2.1-codex`　　依赖：`>= 1.2.0`

---

## 一、设计原则

```
1. 双轨覆盖
   每类能力同时提供 CN（国内无障碍）和 Global 两条路径。
   用户在设置里选"中国大陆"，系统自动切换到国内服务；
   选"全球"则走国际服务。两条路效果等同。

2. 安全第一
   · 只接官方或经过代码审计的 MCP（SSRF/无认证 MCP 全部排除）
   · 所有 MCP 必须配置 API Key 才能 enable（禁止无认证开启）
   · http_request 拦截内网 IP（127.* / 10.* / 192.168.*）
   · install_pkg 仅限白名单包源（pypi.org / npmjs.com）

3. 优雅降级
   MCP 不可用 → 自动 fallback 到 http_request 直调 API
   http_request 被拦截 → 提示用户改用 shell_run + curl
   任何工具失败 → 明确报错，不静默吞掉

4. 工具分层
   原生函数（最优） > MCP（外部服务）> CLI/shell_run（万能兜底）
```

## 三、智能体强度缺口（复审新增）

> 复审结论：工具广度只是 Codex 的一半，另一半是智能体强度。
> 以下 5 项不补，工具再多也只是"能调用"，做不到"自主拿下"。

### N1：编程任务模型路由（P0，影响最大）

Codex 用为 agentic coding 专项微调的模型；Anima executor 用通用 deepseek-v4-pro，
几十轮工具循环容易迷路。**这是最大、工程上也最便宜的杠杆。**

```python
# executor_worker.py：编程任务模型升级链
# relay 已配置 → Claude-Sonnet-4.6（agentic 能力最强的可达模型）
# relay 未配置 → deepseek-v4-pro（最强直连）
def _coding_model(self) -> str:
    from agent_base import MODEL_REGISTRY
    key_fn, base_url, _ = MODEL_REGISTRY["Claude-Sonnet-4.6"]
    if key_fn() and base_url:
        return "Claude-Sonnet-4.6"
    return "deepseek-v4-pro"
```

设置页给开关：「编程任务自动使用最强模型」（默认开，提示消耗更高）。

### N2：`update_plan` 计划可见性工具（P0）

Codex 长任务时维护用户可见的 todo 清单。Anima 只有 tool_start/tool_done 事件流——
看得到"在干什么"，看不到"打算干什么、还剩什么"。长任务信任感的关键。

```python
# xi_worker.py 新增
_session_plans: dict[str, list] = {}   # session_id → steps

def _update_plan(steps: list[dict], session_id: str = "") -> dict:
    """Agent 维护自己的执行计划。每个 step: {text, status: pending/doing/done}
    调用即覆盖整个计划（Agent 全量重报），并通过 WS 推送给前端渲染清单卡片。
    """
```

系统提示加一条铁律：**3 步以上的任务，动手前先 update_plan，每完成一步更新状态。**
前端：聊天区顶部固定显示计划卡片（✅/🔄/⬜ 三态）。

### N3：后台 Agent 任务（P1，云端 Codex 核心体验）

Codex 的杀手锏是"提交任务→走人→回来收结果"。`long_run` 只覆盖后台跑**命令**，
没覆盖后台跑**整个 Agent 会话**。

复用现有 `TaskRegistry`（M12 断线重连）作地基：

```python
# backend/routes 新增
# POST /agent/executor/run_async  → 立即返回 {agent_task_id}
#   executor.run() 包成 asyncio.Task 注册进 TaskRegistry
# GET  /agent/tasks/{id}          → 查询状态/进度（已完成轮数、当前计划）
# 完成时：系统通知（已有 notifier.py）+ 前端任务中心标记完成
```

### N4：`delegate_parallel` 并行子代理（P1）

已验证：`orchestrator.delegate` 是 `t.start(); t.join()` —— 派一个等一个，纯串行。
Codex 8 路并行。"把这 5 个模块分别重构"类任务 Anima 要排队跑 5 倍时长。

```python
# orchestrator.py 新增
def delegate_parallel(tasks: list[dict],
                      allowed_roles: set | None = None) -> dict:
    """并行派发多个子任务。tasks: [{role, task, context?}, ...]
    实现：每个任务一个线程（复用单个 delegate 的逻辑，去掉 join 串行化），
    全部完成后汇总返回 {results: [...]}。
    上限 4 路并行（MAX_PARALLEL=4，预算和 API 限速考虑），超出排队。
    受现有 _MAX_DEPTH / _MAX_TREE_DELEGATIONS 预算约束。
    """
```

### N5：安全定位声明（P0，文档约束）

**Codex 在隔离沙箱里跑，删错文件无所谓；Anima 跑在用户真机上。**
因此 Anima 不追求 Codex 式"无确认全自动"，定位是：

```
危险分级执行（依托已有 M14 confirm/Hooks + git_safety）：
  读操作（read/search/glob/map）   → 无确认，全自动
  写操作（write/edit/commit）      → 默认自动，但多文件改动前强制 checkpoint
  危险操作（删除/覆盖大文件/shell 高危命令）→ 走 confirm 卡片，用户确认才执行
  不可逆操作（push/发布/转账类）   → 永远需要用户确认，不提供"全自动"开关
```

照抄 Codex 的全自动是安全事故，这条是 v1.2.1 所有执行类功能的总约束。

## 六、executor 系统提示新增「工具手册」

```
## 工具手册（你的完整能力）

### 文件与代码
- map_project(root)       → 获取项目全景树（第一步必调）
- glob_files(pattern)     → 按文件名找文件（"**/*.test.py"）
- file_read/write/edit    → 读写改文件
- search_code(pattern)    → 正则搜索代码内容

### 执行
- shell_run(cmd)          → 60s 内命令（测试/类型检查/快速脚本）
- long_run(cmd)           → 无超时后台任务（视频渲染/大型构建/模型推理）
- task_poll(task_id)      → 查询 long_run 进度
- task_kill(task_id)      → 终止 long_run
- install_pkg(pkg, mgr)   → pip/npm 安装包

### 视频生产流水线
- file_write("video.html")  → 写 HyperFrames HTML（用 GSAP 做动画）
- long_run("npx hyperframes render video.html -o out.mp4")
- task_poll(...)            → 等渲染完（30s-5min）
- read_image("frame.png")   → 截帧验证效果
- 如果连了 mcp-video：直接调 trim/merge/subtitle/add_audio

### 网络与 API
- web_search(query)       → 搜索（CN 走 Jina，Global 走 Exa）
- fetch_url(url)          → 读网页内容
- http_request(method, url, body) → 直调任意 REST API

### 文档读取
- read_pdf(path)          → 读 PDF 文本（需求文档/论文/合同）
- read_image(path)        → 读图片/截图（设计稿/UI 截图/图表）

### Git 工作流
- git_status(path)        → 查变更
- git_diff(path)          → 查 diff
- git_commit(path, msg)   → 本地提交（不 push）
- git_log(path)           → 查提交历史
- git_create_branch(path, name) → 新建分支

### 安全网
- checkpoint(path)        → 改动前打快照
- rollback(path, id)      → 回滚到快照

### 典型任务模式
渲染视频：install_pkg("moviepy") → file_write(脚本) → long_run → task_poll
批量短视频：file_write(video.html) → long_run(hyperframes render) → task_poll
调第三方 API：http_request → 处理数据 → file_write
按需求文档写代码：read_pdf → 理解需求 → 写代码 → 跑测试
复现 UI 设计稿：read_image(截图) → 写 HTML/CSS → 验证
```

## 七、安全清单

| 安全点 | 实现方式 |
|---|---|
| **http_request 内网拦截** | 拒绝 `127.*` / `10.*` / `192.168.*` / `172.16-31.*` / `localhost` |
| **install_pkg 包源限制** | 只允许 pypi.org 和 registry.npmjs.com，禁止私有源 |
| **long_run 资源限制** | 单任务最大内存 4GB；超 4 小时自动终止 |
| **MCP 必须认证** | enabled: true 的 MCP 如无 token 则 warn 提示 |
| **shell_run 危险命令** | 已有 `_is_dangerous()` 拦截；新增 curl 上传凭证文件的模式 |
| **read_image 大文件拒绝** | 超 5MB 拒绝，防止 token 爆炸 |
| **read_pdf 大文件分页** | 超 100 页时只读指定范围 |
| **git_commit 安全约束** | 空 message 拒绝；不 push；不操作 .ssh / .env 文件 |
