## 三、三个内核改动（一次投入，解锁多个功能）

这是 v1.2.0 唯一需要动 `AgentBase` 核心的地方。做对它们，后面全是加积木。

### 内核 1：工具分发异步化 —— 解锁 MCP + 任何异步工具

`_execute_tool` 改 async，加 `iscoroutine` 守卫。**同步工具返回 dict，`iscoroutine` 为 False，行为完全不变**——这是向后兼容的全部保证。

```python
# agent_base.py — 唯一的核心改动
async def _execute_tool(self, name: str, args: dict) -> dict:
    if name not in self.tool_dispatch:
        return {"error": f"未知工具: {name}"}
    try:
        result = self.tool_dispatch[name](**args)
        if inspect.iscoroutine(result):      # ← 新增 3 行
            result = await result
        return result
    except PermissionRequest:
        raise
    except TypeError as e:
        return {"error": f"工具参数错误: {e}"}
    except Exception as e:
        return {"error": f"工具执行异常: {e}"}
```

调用点 `agent_base.py:398` 改一个词：`result = await self._execute_tool(name, args)`。

**为什么安全**：全局单一调用点；现有 13 个工具全是同步返回 dict；新增 `test_async_dispatch.py` 锁定"同步工具走 async 路径结果不变"。194 个测试不受影响。

### 内核 2：任务注册表 + 流式协议 v2 —— 一块基建关掉两个 P0

`ws_manager.py` 现在 `current_task` 是 per-agent 单槽，第二个任务会覆盖第一个——这是"提交走人"做不了的根因。新建 `task_registry.py`：任务 = 主循环上存活的 `asyncio.Task`，状态落 SQLite，WS 断开重连可重新 attach 拉回流。

同时把 `_handle_stream` 已经收到的 token 真正发出去（`assistant_delta` 事件）——"看着她写代码"代码里只差这一步。

### 内核 3：确认 / Hook 拦截点 —— 一个 choke point 关掉两个功能

`_execute_tool` 是所有工具的唯一咽喉。在它前后挂 `pre_tool`/`post_tool` hook + 危险操作 `await confirm(...)` 往返。确认机制复用内核 1 的异步能力 + 内核 2 的 WS 往返。

> 依赖关系：**内核 1 是地基**（MCP、确认都依赖它）。先做内核 1。

## 四、MCP 协议支持（最大杠杆，完整设计）

### 4.1 为什么这是杠杆之王 —— 理由和直觉不太一样

"一个协议 = 无限集成"对，但对 Anima 最值钱的不是"接入更多"，是"**停止手写**"。已经手写了 `feishu_bot.py` / `wechat_bot.py` / notion——每个都是几百行维护负担。MCP 让以后不再写这种胶水，甚至可以把现有集成逐步迁成 MCP server。这才是省命的地方。

### 4.2 架构总览

```
┌─────────────────────────────────────────────────────────────┐
│  XiWorker (主循环)          子员工 executor (独立线程+独立 loop) │
│      │                            │                            │
│      │ run() 前 _sync_mcp_tools() │                            │
│      ▼                            ▼                            │
│  self.tool_defs ← mcp__github__create_issue 等(命名空间隔离)    │
│      │                            │                            │
│      ▼ await _execute_tool        ▼ _execute_tool(同步阻塞)     │
│  call_threadsafe ─在主循环?─是→ 直接返回 coro，在主循环 await     │
│                    └─否(子线程)→ run_coroutine_threadsafe        │
│                                  → 阻塞子线程等(同 shell_run)     │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
                  MCPManager (单例, 持有主循环引用)
                   _sessions: {server → 长连接 ClientSession}
                   _tools:    {server → [工具元数据缓存]}
                           ▼
       stdio 子进程 (npx @mcp/server-github)  |  SSE/HTTP (远端 server)
```

### 4.3 关键设计决策

**① 用官方 `mcp` Python SDK**，不自己实现 JSON-RPC。`requirements.txt` 加 `mcp>=1.0`。SDK 需 Python 3.10+——代码已在用 `str | None` / `tuple[str,str,str]`，满足（发版前确认运行时版本）。

**② 命名空间隔离 `mcp__<server>__<tool>`**。两个 server 都有 `search` 不会撞；前缀让 `_sync_mcp_tools` 能干净地"只换 MCP 工具，不碰原生 13 个"。（这正是 Claude Code 的做法。）

**③ Schema 直通**。MCP 的 `inputSchema` 本身是 JSON Schema，和 OpenAI function-calling 的 `parameters` 近乎 1:1，套壳即可。

**④ 跨线程异步桥（整个设计最硬的一块）**。难点：MCP 的 session 绑定主循环，但子员工（`orchestrator.py`）在**独立线程 + 独立 `asyncio.run`** 里跑。解法是一个"看场合"的分发器：

```python
# mcp_client.py
class MCPManager:
    main_loop: asyncio.AbstractEventLoop = None
    _sessions: dict[str, "ClientSession"] = {}
    _tools:    dict[str, list] = {}

    @classmethod
    async def boot(cls, loop):
        cls.main_loop = loop
        for srv in _load_mcp_config():            # config.yaml: mcp.servers
            if srv.get("enabled"):
                try:
                    await cls._connect(srv)        # 握手 + list_tools
                except Exception as e:
                    cls._mark_error(srv["name"], e)  # 单个失败不崩主程序，排除其工具

    @classmethod
    async def acall(cls, server, tool, args) -> dict:
        sess = cls._sessions.get(server)
        if not sess:
            return {"error": f"MCP 服务 {server} 未连接"}
        res = await sess.call_tool(tool, args)
        return _content_to_dict(res)              # content blocks → 简洁 dict

    @classmethod
    def call_threadsafe(cls, server, tool, args):
        """同步入口。主循环里→返回 coro(交给 async _execute_tool await)；
        子员工线程里→marshal 回主循环阻塞等，行为与 shell_run/web_search 一致。"""
        coro = cls.acall(server, tool, args)
        try:
            running = asyncio.get_running_loop()
        except RuntimeError:
            running = None
        if running is cls.main_loop:
            return coro                            # iscoroutine→True→在主循环 await
        return asyncio.run_coroutine_threadsafe(coro, cls.main_loop).result(timeout=120)
```

为什么不能简单全用 `run_coroutine_threadsafe`：主 agent（xi）**就跑在主循环上**，在主循环里 `.result()` 阻塞等一个需要主循环来跑的协程 = **死锁**。所以必须分场合——这也正是内核 1（异步 `_execute_tool`）是前置依赖的原因。

**⑤ 第 5 块能力积木**（对 `capabilities.py` 唯一的增量）：

```python
def _mcp_cap(agent_id: str) -> Capability:
    from mcp_client import MCPManager
    snap = MCPManager.snapshot()        # 当前已连接 server 的工具快照
    return Capability("mcp", snap.tool_defs, snap.dispatch, snap.prompt_fragment)

_FACTORIES["mcp"] = _mcp_cap            # 现有 4 块工厂一行不动
```

`snapshot()` 生成命名空间化的工具定义与分发：

```python
@classmethod
def snapshot(cls) -> "MCPSnapshot":
    defs, dispatch = [], {}
    for server, tools in cls._tools.items():
        for t in tools:
            name = f"mcp__{server}__{t['name']}"
            defs.append({"type": "function", "function": {
                "name": name,
                "description": t.get("description", ""),
                "parameters": t.get("inputSchema") or {"type": "object", "properties": {}},
            }})
            # 闭包绑定，避免循环变量晚绑定
            dispatch[name] = (lambda s, tn: (lambda **kw: cls.call_threadsafe(s, tn, kw)))(server, t["name"])
    return MCPSnapshot(defs, dispatch, _compose_mcp_fragment(cls._tools))
```

`XiWorker.CAPS` 从 `["execution","web","divination","orchestration"]` → 加一个 `"mcp"`。完事。

**⑥ 热加载（关键 UX）**。MCP server boot 时异步连，可能晚于 XiWorker 构造；用户也可能运行中加 server。所以 `XiWorker.run()` 开头调 `_sync_mcp_tools()`——它已在每轮 run 前刷 system_prompt（`xi_worker.py:181`），顺手把 MCP 工具并进来，靠 `mcp__` 前缀只换 MCP 子集：

```python
def _sync_mcp_tools(self):
    from mcp_client import MCPManager
    snap = MCPManager.snapshot()
    base_defs = [d for d in self.tool_defs if not d["function"]["name"].startswith("mcp__")]
    self.tool_defs = base_defs + snap.tool_defs
    self.tool_dispatch = {k: v for k, v in self.tool_dispatch.items() if not k.startswith("mcp__")}
    self.tool_dispatch.update(snap.dispatch)
```

用户加完 server 下一句话就能用，**无需重启**。

## 七、设计立场（取舍的真话）

1. **别照搬 Codex 的"每任务一个云端容器"。** 那砸了"本地隐私/数据不出机器"的命根——表里自己标的"Anima 独有"。M12 异步任务做成**本地 daemon 后台任务**，不是云沙箱。把"本地异步"当卖点。

2. **Docker 沙箱对目标用户是最低 ROI 的一项。** 中国学生/年轻人，Windows Home + WSL2 摩擦、机房限制，很多人装不上也不愿装 Docker。硬依赖会劝退。建议：**这一项故意做得比 Codex 弱**——宿主机执行为默认，沙箱为高级选配，把"安全"的力气压到**确认机制(M14) + 已有的 git checkpoint** 上。这才是无 Docker 的本地安全故事。故排到 M15、标"可选增强"。

3. **流式 token 是"高感知、极低成本"，该提前。** `_handle_stream` 已逐 token 收到，只是没发。"看着她写代码"的体验值远超工作量。如需一周内能 demo 的爽点，它可从 M12 单独抽出先做。

4. **MCP 做完后，回头把 feishu/wechat 评估迁成 MCP server。** 不是 v1.2.0 的事，但记一笔：手写集成越多，不迁的利息越高。
