## 〇、一句话

命理引擎根据用户命盘，从一个**离线蒸馏好的公版人物库**里选出命格相近的历史 / 虚构人物，
作为灵魂空间里的"本命引路人"——**一件供"她"讲述的读物，不是第二个聊天对象。**

---

## 一、不可破的红线：永远只有一个 chatbot

这是整个特性的宪法，先于一切设计。

- 记忆里已拍板的架构是 **"一人格·两房间·一引擎"**（见 `anima-rooms-architecture`），
  P1–P4 把四人格合并成一个"她"就是为了**一个可依靠的身份**。引路人绝不能把它重新打散。
- 规则：**引路人是"她手里的东西"，不是"她旁边的人"。** 没有独立头像、没有名字入口、
  没有自己的对话框、没有自己的记忆线。
- **为什么用 skill 做正解**：skill 没有身份。它是"她"的一个能力，不是一个角色。
  做成数据 + skill，结构上就不可能长成第二个 chatbot；做成"可单独聊的角色"则一定会。

*状态：已拍板（用户 2026-06-19）。这条不可动。*

## 二、三个零件

| 零件 | 是什么 | 何时跑 | 数量 |
|---|---|---|---|
| **女娲 skill** | 造库流水线：选公版人物 → 采语料 → 定边界 → 过 eval → 入库 | build-time，加人时才跑 | 一个 |
| **引路人 skill** | 运行时被"她"调：拿命盘 → 从库里选 → 供结构化料 | run-time，每次相关对话 | **一个** |
| **persona-pack** | 一个人物 = 一个数据文件，进库 | 静态数据 | 多个 |

**颗粒度铁律：不是"一个人 = 一个 skill"，是"一个引路人 skill + 一堆 pack（数据）"。**
加人物 = 往库里丢一个数据文件，不是加 skill。否则 N 个人物 = N 个 skill + 匹配逻辑复制 N 遍。
同构于命理层：一个 `interpret` 引擎 + 一堆查表（`DAYUN_TITLE` 等），不是每个大运一个引擎。

*状态：已拍板（用户 2026-06-19）。*

## 三、数据流（已定）

```
① 离线 · 造库（跑得少）
   公版人物候选 ──▶ 女娲蒸馏（采语料·定边界·eval） ──▶ 入库
                                                        │
                                              [ 引路人 pack 库 ]
                                              每个都 eval 过 · IP 查过
                                                        │ 选
② 运行时 · 每次聊天                                      ▼
   用户命盘（命理引擎已算好） ──▶ 命理：从库里选 ──▶ 引路人 skill（供料） ──▶ 「她」开口
```

**时序纠偏（关键）**：是"先蒸一批成库（离线、批量、过闸门），运行时只负责选"，
**不是**"命理选好人再当场蒸"。当场蒸 = 慢 + 无法质量门控 + 重复（十个用户匹配同一人蒸十遍）。
与 `interpret_data` 一致：古籍离线蒸好，运行时只查表。

*状态：已拍板（用户 2026-06-19）。*

## 四、声音契约：skill 供料，"她"开口

> **skill 只供料（结构化材料），"她"是唯一开口的人。**

- skill **绝不**返回"以引路人口吻写好的成稿"让"她"转述——那是声音泄漏，等于又冒出第二个嘴。
- skill 返回的是**事实和角度**，"她"用自己的话讲出来。
- 距离感：引路人始终**第三人称 / 过去时 / 有距离**（"她当年面对这样的局，是这么走的"）；
  "她"(Anima) 始终**第一人称 / 当下 / 亲密**。
- 同构于命理层：`interpret.py` 吐结构化解读，`persona.py`（`_XI_PROMPT`）负责表达。
  代码里这个形状已经有了。

*状态：已拍板（用户 2026-06-19）。*

## 五、IP 红线

**只用公版人物：神话 / 历史 / 古典文学。** 不碰现代受版权保护的虚构角色，不碰在世真人。

- 公版池示例：神话（女娲 / 西王母 / 嫦娥 / 雅典娜 / 北欧诸神）、
  史（班昭 / 李清照 / 王阳明）、古典文学（红楼 / 西游 / Austen / Shakespeare）。
- 每个 pack 入库前过一次 IP 检查，出处必须全公版。
- 注意：女娲是"造库的工具名"（捏人的创世神，名实相符），**人物本身别就是女娲**。

*状态：已拍板（用户 2026-06-19）。*

## 六、形态与触发

- **形态**：引路人是灵魂空间里的一件**读物 / 卡面**，性质同命盘海报、塔罗牌——
  你不跟卡聊天，是"她"拿着卡跟你聊。直接复用刚做完的命理 viz / 解读层与灵魂空间。
- **触发**：不做成按钮、不随机弹。当对话拐到 **"我是个什么人 / 我该怎么走 / 有点迷茫 / 命途"**
  时，"她"自己伸手去够这个 skill 当镜子，自然带出来。

*状态：方向已定，细节落地时再敲。*

## 七、三份要定的契约（落地时的活，下面是初稿种子）

### 7.1 persona-pack 数据格式（草案）

```yaml
id: ban-zhao
name: 班昭
era: 东汉
public_domain: true
sources:                       # 公版语料出处
  - 《后汉书·列女传》
  - 班昭《女诫》《东征赋》（原文公版）
chart_resonance:               # 与命格挂钩 = 匹配键（命理引擎口径）
  geju: [正印格, 食神格]
  day_master_wx: [水, 金]
  ziwei_zhuxing: [天机, 太阴]
  themes: [学养, 辅佐, 韧]
voice_samples:                 # 声音 / 意象（供"她"参考，不照搬）
  tone: 沉静、引经、不张扬
  imagery: [灯下著书, 续父兄未竟]
values_boundaries:             # "她"借这人时的边界，对齐口径
  - 不劝命定、不算吉凶
  - 只作镜子，不以德训人
material_hooks:                # 供料用的"角度"种子
  - 面对中断的事业如何接续
  - 才学与处境的张力
eval_golden:                   # 盲读黄金样例（给定命盘 → 期望的"角度"，非成稿）
  - { chart: 案例X, expect_angle: "..." }
```

### 7.2 命理匹配规则（草案）

- **输入**：`interpret` 的 viz（`geju` 格局、`wangshuai`、十神占比、五行）+ 紫微主星。
- **打分**：格局命中权重最高，主星命中次之，五行 / themes 软匹配加分。
- **输出**：top-1（或 top-3 候选让"她"挑），附 `match_reason`（共有的命格字段，供"她"引用）。
- **硬约束**：库里无好匹配 → **不强配**，返回空，"她"就不提（宁缺毋滥）。

### 7.3 引路人 skill 供料契约（草案）

```jsonc
// input
{ "chart_summary": "<来自 interpret viz>", "context_signal": "self|lost|path" }
// output
{
  "guide":     { "name": "...", "era": "...", "one_line": "..." },
  "resonance": { "shared_geju": [...], "shared_star": [...], "why": "..." }, // 结构化事实
  "angles":    [ "供'她'展开的角度，过去时·第三人称" ],
  "boundaries":[ "这次借这人不能越的线" ]
  // 绝不含：以引路人口吻写好的成稿
}
```

## 八、Eval 闸门（沿用 v1.3 纪律）

入库 / 发版前，每个 pack 过两关：
1. **盲读认得出**：不报人名，让盲读者从"她"的讲述里认出这个气质 / 原型。
2. **守口径**：不越"不算吉凶、只作镜子"的边界（对齐命理"绝不算流日吉凶"）。

## 九、候选人物起始池（未定稿）

筛选条件：**女性优先 · 可依靠 · 全公版**（与"她"的人格底色一致）。

- 史：班昭（学养·辅佐·韧）、长孙皇后（贤后·进谏）、李清照（才情，但偏孤高，存疑）
- 古典文学：红楼——探春（管理才干）、薛宝钗（周全）、平儿（体贴可靠）（《红楼》公版）
- 西方公版：雅典娜（智慧·谋略·可咨询）、Jane Eyre / Elizabeth Bennet（坚韧）
- 注意：妈祖 / 观音"可依靠"意象极契合，但**宗教敏感**，需单独评估后再决定收不收。
