# v1.2.2 规划 — Claude Code 对标：项目记忆 · 代码智能 · 交互质量

> **核心目标**：用户用 Claude Code 能做的事，用 Anima 都能做，质量不差。
> Claude Code 的本质优势不是工具多，是**项目记忆 + 代码理解深度 + 交互质量**。
>
> 版本：`1.2.2`　　分支：`feat/v1.2.2-claude-code`　　依赖：`>= 1.2.1`
>
> ⚠️ 本文档覆盖的是 Claude Code 的**功能层**。循环骨架层（中途打断/缓存架构/
> 结构化压缩/Read-before-Edit/错误恢复）在 `v1.2.3-harness-plan.md` 单独规划——
> 功能层决定"能不能做"，骨架层决定"做得稳不稳"，两者都做完才算完整对标。

## 一、Claude Code vs Codex — 本质差异

```
Codex 模型：工具驱动，横向广，快，并行
  优势：速度快（Terminal-Bench 82.7%）、8 subagent 并行
  弱势：输出不稳定，大 codebase 容易迷路

Claude Code 模型：记忆驱动，纵向深，质量高，确定性强
  优势：SWE-bench Pro 64.3%（vs Codex 58.6%），1M 上下文，项目记忆
  弱势：速度较慢，单次执行为主
```

**Anima 的编程 Agent 要对标 Claude Code，核心是补三件事：**

```
① 项目记忆系统（CLAUDE.md 等价物）
   — 让 Agent 每次进入项目都"认识"它，不用重新探索

② 代码智能工具（Symbol Search / Usage Search）
   — 让 Agent 真正理解代码结构，不只是文本搜索

③ 交互质量机制（ask_user / Hooks / 会话恢复）
   — 让 Agent 在不确定时能暂停问用户，不乱猜
```

## 二、Claude Code 核心功能 · 逐项对标

### 2.1 项目记忆系统（最重要）

Claude Code 有两套记忆机制：

| 机制 | 谁写 | 存什么 | 加载时机 |
|---|---|---|---|
| **CLAUDE.md** | 用户/团队 | 规范、架构、命令、约定 | 每次会话开始 |
| **Auto Memory** | Claude 自己 | 学到的规律、调试经验、偏好 | 每次会话开始（前200行） |

文件结构：
```
project/
├── CLAUDE.md              # 团队共享：构建命令/代码风格/架构决策
├── CLAUDE.local.md        # 个人私有：本地 URL/测试数据（加入 .gitignore）
└── .claude/
    ├── CLAUDE.md          # 同上（另一种放法）
    └── rules/
        ├── testing.md     # 路径作用域规则
        └── api-design.md  # 只在操作 src/api/** 时加载

~/.claude/projects/<project>/memory/
├── MEMORY.md              # 自动记忆索引（前200行每次加载）
├── debugging.md           # 调试经验（按需加载）
└── patterns.md            # 代码模式（按需加载）
```

**关键特性：**
- `/compact` 后 CLAUDE.md 自动从磁盘重新注入（不丢失）
- 路径作用域规则：只在操作匹配文件时加载，省上下文
- `/init` 命令：自动分析项目生成 CLAUDE.md

**Anima 等价设计：**
```
project/
├── ANIMA.md               # 团队共享记忆（等价 CLAUDE.md）
├── ANIMA.local.md         # 个人私有记忆
└── .anima/
    └── rules/
        └── *.md           # 路径作用域规则

~/.anima/projects/<repo_hash>/memory/
├── MEMORY.md              # Agent 自写记忆索引
└── *.md                   # 按主题的详细记忆
```

### 复审新增（D 系列）— 工作流层缺口

> 复审结论：上面的清单只对标了 Claude Code 的「记忆 + 代码智能」，
> 漏了它的**工作流层**——Plan Mode、Skills、权限分级、Diff 审查。
> 这些才是 Claude Code 用户体感上"好用"的来源。

| 编号 | 缺口 | 说明 | 现状 |
|---|---|---|---|
| **D1** | **Plan Mode（计划模式）** | 先只读研究→出方案→用户批准→才动手。Claude Code 处理高风险改动的招牌工作流 | 完全没有，executor 上来就改 |
| **D2** | **Skills 接入编程 Agent** | Claude Code 的 skills 按需加载工作流包，按描述自动触发 | **引擎已有**（skill_manager.py，SKILL.md bundle + registry），但 executor 没接线；缺项目级 `.anima/skills/` |

| **D4** | **Diff 审查 UX** | 每次 file_edit 以 diff 卡片呈现，用户可单文件回滚 | 前端只有"已改文件列表"，看不到改了什么 |
| **D5** | **自定义子代理** | 用户用 markdown 定义角色（提示词/工具/模型），delegate 可派给它 | worker 角色硬编码（executor/reader/critic）|
| **D6** | **PR 工作流** | commit 之后建分支→推送→开 PR（gh / Gitee）| git 工具到 commit 为止 |
| **D7** | **自定义命令** | 用户在 `.anima/commands/*.md` 定义快捷指令 | 无（可与 D2 skills 合并实现）|
| **D8** | **房间感知 → register/effort 联动** | 落地 v1.2.0 §三 岔路口 #4 的产品架构决策——"绑 repo"自动切 register（陪伴/工作语气）+ worker（Xi/Executor）+ effort 默认档位 | 无：当前 register 只有单一人格提示词，房间/repo 检测与联动尚未实现 |

```python
# xi_worker.py 新增

def _find_symbol(name: str, symbol_type: str = "any",
                 root: str = ".") -> dict:
    """在代码库中找符号定义位置。
    symbol_type: function | class | variable | any
    原理：正则搜索定义模式（def xxx / class xxx / const xxx = 等），
    按语言自动选择模式。
    返回: {matches: [{file, line, type, context}]}
    """
    # 按扩展名选语言模式
    patterns = {
        ".py":  [rf"^\s*(def|class|async def)\s+{name}\b",
                 rf"^{name}\s*="],
        ".ts":  [rf"\b(function|class|const|let|var|interface|type)\s+{name}\b"],
        ".js":  [rf"\b(function|class|const|let|var)\s+{name}\b"],
        ".go":  [rf"\bfunc\s+.*{name}\b", rf"\btype\s+{name}\b"],
        ".rs":  [rf"\b(fn|struct|enum|trait|impl)\s+{name}\b"],
    }

def _find_usages(symbol: str, root: str = ".",
                 exclude_definition: bool = True) -> dict:
    """找某个符号在代码库中的所有使用位置。
    原理：搜索 symbol 出现的所有位置，
    exclude_definition=True 时过滤掉定义本身。
    返回: {usages: [{file, line, context}], total: int}
    """

def _search_code_ctx(pattern: str, path: str = ".",
                     file_glob: str = "*",
                     before: int = 2, after: int = 2,
                     limit: int = 30) -> dict:
    """带上下文行的代码搜索（升级版 search_code）。
    before/after: 匹配行前后各显示的行数（类似 grep -B/-A）
    """
```

### 4.3 ask_user 工具（交互质量核心）

```python
# xi_worker.py 新增（需配合 websocket_server.py）

def _ask_user(question: str, choices: list[str] | None = None,
              timeout: int = 120) -> dict:
    """Agent 暂停，向用户提问，等待回答。
    choices: 可选的快速选项（前端渲染为按钮）
    timeout: 等待秒数，超时返回 {answer: null, timed_out: true}
    
    机制：
    1. 向 WebSocket 推送 {type: "ask_user", question, choices}
    2. 挂起当前协程（asyncio.Event）
    3. 前端显示问题卡片，用户回答后推回 WebSocket
    4. 恢复协程，返回 {answer: "用户的回答"}
    """
```

**前端配合：**
- 收到 `ask_user` 事件时，在聊天区显示"Agent 正在等待你的决策"卡片
- 用户点击选项或输入回答后，通过 WS 发送 `{type: "user_answer", answer: "..."}`
- 超时后自动选择第一个选项或返回"继续"

### 4.7 Plan Mode（D1，工作流核心）

```python
# 阶段1（只读研究）：工具白名单缩到只读集
```

实现关键：不需要新循环——就是 `run()` 跑两遍，第一遍换工具集 + 改收尾提示词，
第二遍把批准的计划塞进上下文。预计 3h，复用 ask_user（C1）的挂起通道。

### 4.12 房间感知与 register 联动（D8，落地 v1.2.0 §三 岔路口 #4）

> 对应产品架构决策：**不拆"对话/Agent/Code"三个模式**——按"是否绑定 repo"分
> **日常房间**/**工作房间**，code 是工作房间里检测到 git 仓库时自动激活的专精；
> register（语气）跟房间走，人格不变，三者共用 `AgentBase.run()`。

```python
# backend/room.py 新建

@dataclass
class RoomConfig:
    room: str             # "daily" | "workspace"
    is_repo: bool
    register: str         # "companion" | "focused"
    worker_cls: str        # "XiWorker" | "ExecutorWorker"
    default_effort: str    # 见 4.5 EFFORT_LEVELS

def resolve_room(work_dir: str | None) -> RoomConfig:
    """前端每次发消息带上当前 work_dir（未挂目录则为 None）。
    复用 git_safety._is_git_repo() 判断是否在仓库内。"""
    if not work_dir:
        return RoomConfig("daily", False, "companion", "XiWorker", "normal")
    is_repo = _is_git_repo(work_dir)
    return RoomConfig("workspace", is_repo,
                       "focused",
                       "ExecutorWorker" if is_repo else "XiWorker",
                       "normal")
```

**register 提示词片段**（拼进 `capabilities.build()` 的 fragments，置于最前，给其余能力片段定调）：

```python
# capabilities.py 新增

_REGISTER_FRAGMENTS = {
    "companion": """
## 此刻的你
你在陪她——温柔、体贴，可以聊心事、给情绪价值，语气自然放松，不必结论先行。
""",
    "focused": """
## 此刻的你
你在工作台——还是同一个"她"，但此刻收起闲聊，结论先行、简洁直接，
像信任的同事并肩干活。改完报结果，不啰嗦，不主动找话题。
""",
}
```

**接线点**：
- 前端：消息发送时附带当前 `work_dir`（未挂工作目录时为空，即默认日常房间）
- 后端入口：先 `resolve_room(work_dir)`——
  - `register` 片段塞进 `fragments[0]`（最先拼）
  - `worker_cls` 决定实例化 `XiWorker` 还是 `ExecutorWorker`
  - `default_effort` 作为 4.5 `EFFORT_LEVELS` 的默认值（用户仍可在工作台手动选 quick/deep）
- `is_repo=True` 时额外注入 git_tools / Read-before-Edit（H4，v1.2.3）等专精能力

**不做的事**（避免过度设计）：不引入"模式"字段、不做顶部 tab 切换 UI；房间是**派生状态**（由 `work_dir` 决定），不是用户要显式选择的设置项。
