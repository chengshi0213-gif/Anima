# Anima 记忆与人格系统规划（v3）

> 2026-06-10 起草（v1），同日升级 v2、v3。背景：用户对当前记忆系统与人格系统表达不满，
> 经代码盘查确认三个痛点——**记忆写不进去 / 检索召回不准 / 人格体验割裂**。
>
> v1 回答了管道问题（有什么/缺什么/怎么补）。v2 在用户反馈后下沉到产品体验层：
> **用户要感知到 Anima 是一个"人"**（初始人格的语体设计：去AI味、输出格式、表情、
> 标点、情绪、口头禅），**并且是一个有记忆、可成长的人**（什么值得记、如何维护、
> 成本、如何被感知；成长 = 记忆升格 + 语体向用户靠拢），**命理占星是了解用户的
> 最好入口**（命盘→画像桥 + 灵魂空间提案）。
>
> v3 用一个成熟的 7 层记忆模型（ChatGPT 系）做外部对照，确认 Anima 已覆盖第 1–6 层
> （第②③层 + 反思升格还更强），**补上唯一真空——第⑦层偏好学习**：从用户对产出物的
> 反应里学"怎么做"的规则（新增 E 程序层记忆 + M10 偏好学习管线），并收紧 M5 注入打分
> 为复合分。详见 §〇.5 七层对账。

## 〇、定位：本规划与 v1.2.x 的关系

v1.2.2 的 A 系列（ANIMA.md + AutoMemory）是**项目记忆**——绑定某个代码仓库的构建命令、
架构约定，服务"工作房间"。本规划处理的是**个人记忆**——"她"对用户本人的长期认知
（身份/偏好/目标/关系/正在做的事），服务"日常房间"也贯穿"工作房间"。

完整的"她认识你"栈：

```
┌──────────────────────────────────────────────┐
│  画像层（v2 新增，L2 洞察，always-on 注入）     │  她懂你是什么样的人
│  由事实层升格 + 命盘先验，每周提炼              │
├──────────────────────────────────────────────┤
│  E 程序层（v3 新增，偏好规则，仅工作房间注入）   │  她懂你要的东西长什么样
│  M10 从产出物 diff 周级抽取，按领域分桶         │  （交付物上越用越懂你）
├──────────────────────────────────────────────┤
│  个人记忆（本规划 M 系列，L1 事实）             │  她知道你是谁
│  ~/.anima/data/memory.db / ~/Anima-Vault     │
├──────────────────────────────────────────────┤
│  项目记忆（v1.2.2 A 系列，已规划未动工）        │  她知道这个仓库怎么回事
│  <repo>/ANIMA.md + MEMORY.md                 │
├──────────────────────────────────────────────┤
│  语言图谱（已实现，lang_profile.py）           │  她知道你怎么说话
│  ~/.anima/data/lang_profile.json             │
└──────────────────────────────────────────────┘
```

人格 P/V 系列与 v1.2.2 D8（房间感知 + register 联动）互补：D8 解决"房间→语气"的
粗粒度切换，P 系列解决"声音统一性"，V 系列（v2 新增）解决"声音本身长什么样"。

### 〇.5 七层记忆模型对账（v3 新增：外部对照定位真空）

用一个成熟的 7 层记忆模型（ChatGPT 系，社区拆解）做镜子，确认 Anima 缺的到底是哪一层。
结论：**第 1–6 层 Anima 都有了（第②③层 + 反思升格还更强），唯一真空在第⑦层。**

| 7 层模型 | Anima 对应 | 状态 | 判断 |
|---|---|---|---|
| ①对话上下文 | `agent_base.run()` 上下文窗口 | ✅ 有 | 持平 |
| ②长期记忆库 | `memory_backend` SQLite+FTS5 / Obsidian 双后端、9 类分区 | ✅ 有 | **更强**：模型是扁平 JSON 数组，Anima 是分类+分区+可迁移后端 |
| ③用户画像 | L2 画像洞察（M2b） | 🔶 规划 | **设计更强**：模型的 Profile 是扁平 JSON；Anima 的 L2 **标来源事实 ID、可审计可纠错、带置信分级** |
| ④RAG 检索 | M4 本地 embedding + M5 话题感知注入 | 🔶 规划 | 落后但已规划。当前纯 FTS5（G4/G5） |
| ⑤记忆生成器 | M1 remember 工具 + §3.1 分级 + M2a 守藏 SOP + M3 闸门 | 🔶 规划 | 持平 |
| ⑥记忆更新 | M7 时效衰减 + M3 冲突不静默覆盖 | 🔶 规划 | 持平 |
| ⑦经验学习库/偏好学习 | **几乎没有** | ❌ **真空** | **唯一真洞 → 本次 v3 补 M10 + E 程序层** |

模型里**没画但 Anima 有**的一层：**反思/升格**（L1 事实→L2 洞察的每周提炼 M2b，
即 Generative Agents 的 reflection 层）。模型把记忆当平铺事实，Anima 已有"事实→洞察"
提炼管线。这一层 Anima 领先，不动。

**对模型的两处批判性修正（不照搬）：**

1. **第④层不上重型向量库。** 模型把 RAG 列为核心、列了 Chroma/Qdrant/Milvus/Weaviate。
   但 Anima 是**单用户、几百条量级**的私人陪伴，不是百万级检索。M4 的本地 `bge-small`
   + SQLite 向量表 + FTS5∪余弦混合召回是对的轻量解，守住"绝不联网上传"。上 Qdrant =
   给一个人的日记装数据中心。维持现方案。
2. **第④层检索打分补复合分。** 现注入是 importance Top-N（G5 病根），模型是纯相似度，
   两个都不够。Generative Agents 的正解是 **复合分 = 相关性 + 新近度 + 重要性** 加权。
   M5 改用复合分排序（v3 已折进 M5，见 §七 M5）。

**第⑦层为什么是最高杠杆的真空：** 见 §四.4。一句话——现规划里"偏好"是用户**说**出来
的事实（B 层），第⑦层是从用户**改**产出物的行为里学出来的规则（E 层）。后者正是
"照片→文案"类生产力场景的核心诉求，落在工作房间，是"生产力北极星 + 越用越懂你"
最直接的兑现。

### 1.2 记忆系统 — 缺什么（按痛点归因）

**痛点① 写不进去（影响最大）**
- G1 「她」本体没有记笔记工具：`capabilities.py` 的 `_FACTORIES` 没有 memory 积木，
  `XiWorker.CAPS = [execution, web, divination, orchestration, mcp]`。
  `persona.py` 给 xi 列了"记忆"能力——**名实不符**。对话中她无法说"我记下了"。
- G2 守藏 SOP 无定时：唯一的"对话→记忆"批量管道靠手点。用户不点 = 永不沉淀。
- G3 无写入质量闸门：同 key 有 upsert，但近义 key 会重复堆积；无重要性过滤策略。

**痛点② 检索召回不准**
- G4 纯 FTS5 关键词匹配：换个说法问旧事就搜不到。无语义/向量检索。
- G5 注入与当前话题无关：注入取"按重要性 Top-N"，不看用户这句话在问什么——
  1500 字预算花在静态清单上，真正相关的旧记忆可能被截掉。

**次级缺口**
- G6 无遗忘机制：没有 last_accessed/时效衰减，过期事实永久占注入预算。
- G7 记忆管理界面薄：没有"看到她记了什么、改错、删除"的列表式管理。

**v2 新增缺口（产品体验层）**
- G12 记忆没有"被感知"的出口：即使 M1-M5 全做完，如果她从不主动引用、没有时间感、
  不会主动想起，用户依然觉得她没记忆。管道是必要条件，不是充分条件。
- G13 没有升格机制：记忆永远是平铺的事实条目，堆一千条也不会变成"懂你"。
  缺事实→洞察的提炼层。
- G14 命盘解读是一次性消费：解读完即散场，结论不沉淀为她对你的理解。
  了解用户的最好入口没有接进记忆。

**v3 新增缺口（七层对照，§〇.5）**
- G17 无偏好学习（第⑦层真空）：现规划的"偏好"只有用户**说**出来的 B 层事实，
  没有从用户**改**产出物的行为里学"怎么做"的规则。她写的文案被改了十次也学不会
  你的口味，每次从零。这是工作房间"越用越懂你"的核心缺口（M10 解，§四.4）。

## 三、记忆内容策略（v2 新增：什么值得记 / 怎么维护 / 成本 / 怎么被感知）

### 3.1 什么值得记——写入分级（M1 prompt 片段与守藏 SOP 共用此标准）

| 层 | 内容 | 例 | 时效 |
|---|---|---|---|
| A 恒定层 | 身份事实 | 生日、家人、职业、出生信息 | 近乎永久 |
| B 偏好层 | 喜恶、习惯、雷点（用户**说**出来的） | 不吃香菜、讨厌被催、习惯夜里工作 | 长期，可被新证据更新 |
| C 状态层 | 正在做的事、近期计划、近期情绪 | 下周去上海出差、最近失眠 | **自带过期**（M7 衰减的主要对象） |
| D 关系层 | 我们之间发生的事 | 她许过的承诺、用户给过的反馈、吵过的架、她说错过的话 | 长期 |
| **E 程序层（v3 新增）** | **怎么做**的规则，从用户**改**产出物的行为里学的（≠B 的"说"） | 文案别空洞抒情要具体细节、代码注释要简、PPT 一页一观点 | 长期，被新 diff 持续修正 |

D 关系层最容易被忽略，但最造"人感"——"上次你说我那句话太冲，我记着呢"
比记住一百条偏好都更像人。守藏 SOP 的提炼 prompt 要显式包含 D 层。

E 程序层是 v3 对照七层模型后补的新类型（详见 §四.4 + M10）。和 B 偏好层的本质区别：
B 是用户**陈述**的喜恶（"我不吃香菜"），E 是从用户**行为**里挖出的产出规则
（她写 A→用户改成 B→抽"讨厌空洞抒情"）。E 管"她怎么交活"，注入**工作房间**的
生成上下文，不进日常聊天的身份层。

**不记**：一次性指令、寒暄填充、可从上下文重建的信息；健康/财务等敏感细节
默认先问一句"这个要记下来吗"再写。

> **落地备注（M1）**：A/B/C/D 直接作为 `memory_backend.MemoryEntry.category` 的存储值
> （字母即分类），与历史分类（user_profile/preference/...）并存。
> `CATEGORY_LABELS` 已加四级标签，`AGENT_MEMORY_CATEGORIES["xi"]` 已扩展为含 A/B/C/D，
> 保证 remember 写入的条目能被 `read_for_agent("xi")` 注入。后续 M2a 守藏 SOP /
> M3 写入闸门 / M7 衰减 / M8 主动想起均可直接按 "A"/"B"/"C"/"D" 字符串过滤，无需概念翻译。

### 3.2 怎么维护

- 写入闸门（M3）：近义 key 合并、单会话上限、importance 过滤。
- **矛盾处理**：新信息与旧记忆冲突时，她不静默覆盖，而是问出来——
  "咦，你之前说的是 X，现在变了？"——维护动作本身就是记忆感知的展示位。
- 审计：用户在灵魂空间（原 M6）可看、可改、可删她记的每一条。
- 遗忘（M7）：时效衰减 + 180 天归档，C 状态层是主要对象。

### 3.3 成本账

- **注入预算分层**（替代现在的单一 1500 字截断）：
  画像层 always-on ~300 字 + 话题相关检索 ~900 字（M5）+ 高重要性兜底 ~300 字。
- 写入：M1 按需工具调用（边际成本≈0）；守藏每日 SOP 只扫当天增量、无新对话跳过、
  用便宜模型档——每天成本在分钱级。
- 升格（M2b）每周一次，与语体复盘（G1）合并跑，成本共摊。

### 3.4 记忆感知五式（G12 的答案——管道是必要条件，五式才是体验本体）

### 4.2 语体靠拢 v2（G16 的答案）

- 现状：lang_profile 启发式统计，单向描述用户。
- 升级方向：
  1. 特征面扩展：emoji 使用率、消息长度分布、英文/术语夹杂习惯。
  2. **三成原则**：她只在形式上向用户靠近三成，七成保持自己——形式接近，
     判断是她的（lang_profile 文档字符串里的原则，显式写进注入提示）。
     镜像太狠 = 恐怖谷 + 丢人设。
  3. 禁区清单：脏话不跟、火星文不跟、她的标点纪律（2.2）不破。
  4. 实施升级：纯规则 → 每周与升格 SOP 合并跑一次 LLM 语体复盘，产出
     "她该怎么微调"而非"用户什么样"。
- 这就是"表达形式、语体习惯向用户靠拢"的落点：用户能模糊感觉到
  "她说话越来越对我的频"，但说不出哪里变了。

**实现说明（2026-06-12 落地，~2h，按预估）**：

- `lang_profile.py::_analyze()` 新增三个特征维度：`emoji_rate`（消息含 emoji

- `get_profile_block()` 从单纯的特征描述升级为包含四段的完整注入块：
  ① 用户语言特征（原有+新增维度的自然语言描述）
  ② 三成原则（"靠近三成，七成保持自己"的显式指令）
  ③ 禁区清单（"脏话/火星文/叠字卖萌不跟、标点纪律不破"的显式指令）
  ④ LLM 语体建议（`llm_advice` 字段，每周复盘产出，如有）

  `lang_profile.json` 的 `llm_advice` 字段，`get_status()` 同步暴露。

### 4.4 偏好学习（v3 新增：第⑦层的答案——交付物上的"越用越懂你"）

§4.1 的升格管线让她懂"你是什么样的人"（情感/认知上的懂）。偏好学习让她懂
"你要的东西长什么样"（**交付物上的懂**）。两者是成长的两条腿，缺一不可——
前者是日常房间的灵魂，后者是工作房间的手艺。

**和 B 偏好层的根本区别**（也是为什么要立 E 程序层这个新类型）：

| | B 偏好层（已规划） | E 程序层 / 偏好学习（v3 新增） |
|---|---|---|
| 来源 | 用户**说**的 | 用户**改**的（行为/隐式反馈） |
| 管的是 | 她知道什么 | 她**怎么产出** |
| 更新 | 一次性陈述 | 持续从 diff 里挖 |
| 注入到 | 身份层（贯穿） | **工作房间生成上下文** |

**三类隐式信号**（M10 抓取）：
1. **显式编辑**：她产出 A，用户改成 B → 存 (A, B) diff 对（最强信号）。
2. **显式吐槽**：「太空洞了」「这段删掉」「别这么正式」→ 存负样本 + 原因。
3. **接受信号**：产出了没改、直接用了 → 正样本（弱但量大）。

**管线**（周级，与 §4.1 M2b 升格 SOP + G1 语体复盘合并跑，成本共摊）：
```
工作房间产出 + 用户反应
  ↓ M10 采集：(产出A, 改后B / 吐槽 / 采纳) 三类信号入库
偏好信号簇
  ↓ 每周 LLM 从 diff 对抽规则（"讨厌X，喜欢Y"）
E 程序层偏好规则     「文案：拒空洞抒情，要具体细节/生活观察/克制表达」
  ↓ always-on 注入工作房间生成上下文
她的下一次产出      第四次不用你改
```

**纪律**（防跑偏）：
- 偏好规则**按领域分桶**（文案/代码/PPT/命盘解读各一组），不跨域污染——
  "文案要克制"不该让她写代码也变扭。
- 规则标来源 diff（同 L2 画像），灵魂空间可看可删——她为什么这么写，可追溯。
- 样本不足不硬抽：一个领域 diff 对 < 阈值（建议 5）时不生成规则，避免一次编辑
  就被当成铁律。
- 与 B 偏好层冲突时以 E 为准但提示用户（"你说过喜欢长文案，但最近三次都删到一半，
  我先按短的来？"）——又一个记忆感知展示位。

**为什么是最高杠杆**：这是"生产力北极星"（[v1.2.0 战略]）下"越用越懂你"最直接、
最可感的兑现——不是情感上的懂，是用三次她就摸到你的口味、第四次省掉你返工。
正是用户那个"照片→文案"项目缺的东西。落点是 Anima 两房间架构的**工作房间**，
不碰日常房间的身份层。

## 五、命理占星：理解她的先验 + 灵魂空间（v2 新增）

### 5.1 命盘→画像桥（M9，G14 的答案）

命盘是结构化的用户画像种子（性格倾向/决策风格/情感模式）。设计：

- 命理解读会话结束后，把**解读结论中关于用户特质的部分**转写为 L2 画像条目，
  标注 `来源=命理, 置信=待验证`。
- 后续真实互动与命理先验吻合 → 置信升级；相悖 → 她修正并在灵魂空间留痕。
- 分寸：**先验不是标签**。她不说"你命里就是这样"，她说"我猜你是那种……我们处久了验证"。
  命理从一次性消费功能，变成她认识你的起点。

**实现说明（2026-06-12 落地，~1.5h，按预估）**：

- `cap_divination.py` 新增第 4 个工具 `record_chart_insight(trait, insight)`：
  晞/Anima 在命理解读快收尾、对用户性格倾向/决策风格/情感模式聊出相对稳定的
  判断时调用，内部调 `memory_injector.write_l2_insight()` 写入一条 L2，
  `importance=2`（M2b 常规洞察为 4，2 即"待验证"的置信分级标记）。
  `ADAPTER_NOTE`/`BRIEF` 补充措辞规范："我猜你是……我们处久了验证"，
  只记反复起作用的稳定特质，不为单次运势/流年调用。
- `scholar_worker.run_weekly_promotion` 的 prompt：列已有 L2 洞察时，
  `importance<=2` 的条目标注"（命理先验，待验证，importance=N）"；
  新增指令 3b——本周 L1 事实与其吻合则同 key 重写、措辞改确定、
  importance 提到 4；相悖则修正 value（"看来和盘面猜的不太一样"）。
  "置信升级/修正"复用 `write_l2_insight` 既有的同 key 合并机制，未新增
  版本历史字段——"留痕"体现为灵魂空间"她记得的我"室里那条 L2 的最新文本。
- 新增 3 个测试（`tests/test_memory_promotion.py`）+ 更新
  `tests/test_yiyi_worker.py` 的工具清单断言（晞现注册 4 个命理工具），
  360 测试全过。

### 5.2 灵魂空间（岔路口 #5——提案：做，但不是第三个房间）

用户提问：命理功能要不要丰富成独立的带密码灵魂空间？

**推荐：做，形态是"带密码的档案馆页面"，不是第三个对话房间/模式。**

- 守住"一人格·两房间·一引擎"决策（任何新空间讨论先过这道门）：
  灵魂空间不是另一个对话界面、不是另一种人格状态，而是**她替你保管的一个上锁抽屉**
  ——内容空间，不是对话空间。不违反架构决策。
- 内含三室：
  1. **我的命盘**——排盘存档 + 历次解读记录（现在解读完即散场，改为可回看）。
  2. **她记得的我**——L1/L2 记忆审计界面（原 M6 升级于此）：分类浏览、看 L2 画像
     及其来源事实、改错、删除。
  3. **我们的时刻**——D 关系层记忆的时间线呈现。
- 密码：复用 `user_auth.py`（PBKDF2 + 激活码离线重置）做**二次验证门**——
  应用登录密码之上独立一道，零新基建，只是再走一次已有校验流程。
- 为什么值得做：命理+情感+画像是全应用最私密的数据，独立上锁有真实的隐私价值，
  也有仪式感；同时把冷冰冰的"记忆管理界面"变成有产品温度的空间——
  **功能性（审计）和仪式感（灵魂空间）是同一个页面，一份工钱两个收益。**
- 工作量：M6 由 2h 升级为 4h（密码门 0.5h + 三室页面 3.5h）。

**实现说明（2026-06-12 落地，实际~5.5h，超预算约 +1.5h）**：

- **「我的命盘」室范围扩大**：实查发现 `cap_divination._tool_paipan` 完全无状态，
  排盘结果从未持久化，与本节"历次解读记录可回看"的设计冲突。经
  AskUserQuestion 与用户对齐，选择**"完整"方案**：新增
  `backend/divination_history.py`（本地 JSON 文件，最多 50 条，纯本地不联网），
  并新增 `POST /divination/paipan`（用存档出生信息排盘+写入历史）、
  `GET /divination/history`、`DELETE /divination/history/{id}` 三个端点。
  这是新基建，约 +1.5h，但用户认为是必要的产品完整性，接受超预算。
- **「她记得的我」室"改错"降为 MVP**：本节原描述"看 L2 画像及其来源事实、
  改错、删除"。"删除"复用既有 `DELETE /memory/entries/{id}`；但"改错"（编辑
  L2 条目文本）没有对应的 PATCH 端点。经 AskUserQuestion 对齐，选择

- 前端落地：`src/index.html` 新增 `tab-soulspace` 面板（密码门复用
  `.ob-card`/`.ob-input`/`.auth-err` 样式，调用既有 `POST /auth/login` 做
  二次验证，零新增后端鉴权代码）+ 三室容器；新增 `src/soulspace.js`（密码门
  逻辑、`switchTab` 包装、三室数据加载与删除）；`src/styles.css` 新增
