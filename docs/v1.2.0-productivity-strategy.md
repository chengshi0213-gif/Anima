## 〇、一页纸结论

> **北极星：把 Anima 从「有灵魂的陪伴」升级为「有灵魂的生产力伙伴」。**
> v1.2.0 的全部动作只为一件事服务——**让用户用 Anima 真能把活干完**，而不只是聊得开心。

四根支柱，一条护城河：

| 支柱 | 对标 | 一句话目标 |
|---|---|---|
| ① 智能体 | **Codex** | 提交即走人的**本地异步任务** + 多步自主执行 + 多 agent 协同 |
| ② 编程 | **Claude Code** | MCP 即插即用 + 流式看她写 + Git 一等公民 + 改测修绿循环 |
| ③ 工作流 | **Claude Workflow / Anthropic agentic 模式** | 把已有的 n8n 式可视化编排，升级成「**可视化 + 智能体原语**」双形态 |
| ④ 设计 | **Claude Design / Anthropic 设计语言** | 自成一套成文的 **Anima Design** 设计体系（token + 组件 + 原则） |
| 护城河 | （三家都没有） | **灵魂 · 记忆 · 命理 · 本地隐私 · 中国模型原生** —— 死守，不为对标而稀释 |

**关键判断**：支柱①②的"地基"在代码里几乎都埋好了（见 `v1.2.0-design.md`）；支柱③有现成的 `workflow.js`(74KB) 可视化引擎做底子；**支柱④是从零的最大空白，也是投入产出比可能最高的一项**——因为"灵魂"必须靠设计落到像素上才有人能感知到。

## 一、四支柱对标研究（结论与出处）

### 支柱① 智能体 —— 对标 Codex（OpenAI）

**Codex 2026 现状**（GPT-5.5，~400 万周活开发者）：
- **统一 App Server 架构**：CLI / VSCode / Web / macOS 桌面 / JetBrains / Xcode 共享一个长连接会话与审批状态——"一处发起，处处可见"。
- **云端隔离沙箱**：每个任务一个容器，**执行期间断网**，只能碰用户显式提供的仓库与预装依赖。安全靠"环境隔离"。
- **极强自主性**：演示过单任务 **1000+ 次连续工具调用无人介入**；模型提交前自检。
- **fire-and-forget 云委托**：`codex cloud` 在终端里 triage/启动云任务、回捞改动。
- **subagent 工作流**：仅在用户显式要求时才 spawn 子 agent（因为更费 token）。
- **MCP**：`~/.codex/config.toml` 配 STDIO/HTTP server，会话启动自动拉起。
- 开源（Rust CLI）。

**口碑**：赢在**速度、自主性、单任务成本、团队多 agent 协同**。"build me a CLI that does X"这类自包含任务，干净云环境反而是优势。

**Anima 对照**：异步任务（❌→大差距）、多步自主（⚠️ ReAct 有但浅）、并行（❌ delegate 串行）、Git（⚠️ 只有 checkpoint）。
**取舍**：**抄"提交走人"的体验，但不抄"云端容器"**——那砸了本地隐私护城河。做成**本地 daemon 异步任务**，把"数据不出机器的异步"当卖点。（详见 `v1.2.0-design.md` M12 / 第七节）

### 支柱② 编程 —— 对标 Claude Code（Anthropic）

**Claude Code 2026 功能体系**（Opus 4.7）：
- **斜杠命令 / Skills（已统一）**：`/<name>` 插提示词模板；Skill = 带领域逻辑+参数+附带文件的命名包。
- **Subagents**：独立上下文窗口的子会话（Explore 只读探索 / Plan 只规划 / general）。
- **Hooks**：`PreToolUse` 在每次工具调用前跑，exit code 2=拒绝、0=放行。
- **MCP**：与外部工具对话的统一协议。
- **Plan Mode**（Shift+Tab）：非平凡任务先出方案再动手。
- **Plugins**：把 skills+subagents+commands+hooks+output-styles+MCP 打成一个可安装包，团队/市场共享。

**口碑**：赢在**代码质量**（盲评 67% 更干净）、**长上下文推理**、**本地不出机器**、**展示推理过程**、**危险操作前先问**、**prompt 缓存省 90%**、**可编程控制**（hooks+subagents 塑形）。

**Anima 对照**：MCP（❌ 每个集成手写，最大差距）、流式（⚠️ 有 thinking steps 但粗）、项目感知（⚠️ 雏形）、权限确认（⚠️ 只有 git checkpoint）、Hooks（❌）。
**取舍**：MCP 是最大杠杆（停止手写胶水）；流式 token 是"高感知低成本"该提前；Hooks/确认在 `_execute_tool` 单一咽喉一并做。**全部已在 `v1.2.0-design.md` M11/M14 设计完毕**。

### 支柱③ 工作流 —— 对标 Claude **Dynamic Workflows**（动态工作流，2026-05-28 随 Opus 4.8 推出）

**⚠️ 重大修正**：最初把"Claude workflow"理解成《Building Effective Agents》的 agentic 范式——错了。Anthropic 真正推出的新功能是 **Dynamic Workflows（动态工作流）**，这是一个全新的、更高维度的东西：

**Dynamic Workflows 实际形态**（Claude Code，研究预览，Enterprise/Team/Max）：
- 用户**用自然语言描述任务** → **Claude 在运行时自己写一段 JavaScript 编排脚本**（不是预定义 DAG，是运行时动态生成）。
- runtime 在**后台执行**该脚本，用户会话保持响应。
- 脚本拉起**几十到上百个（最多 1000）并行子 agent**，每个管一块独立职责。
- 子 agent **互相挑战彼此的结论**（多路推理并行，类"多 agent dreaming"）→ **独立验证每个发现** → **综合汇报**。
- 范式：**plan → 上百并行子 agent → verify → report**。
- 杀手用例：全库 bug 猎杀、安全审计、profiler 优化审计、大规模迁移（框架替换/API 弃用/语言移植跨数千文件）。**Bun 用它把 75 万行 Zig 移植到 Rust，11 天、99.8% 测试通过**（原本需 6–12 个月一个团队）。
- 同期还有 **Claude Cowork**（面向知识工作的 agentic AI）。

**认知错位（三层，必须分清）**：
- **Anima 现有的"工作流"**（`workflow.js` 74KB + `workflow-canvas.js`）是 **n8n / 扣子式可视化自动化编排**：用户**手搭** DAG，节点类型齐全。**=低代码自动化形态。**
- **Anthropic 5 模式**（routing/parallel/orchestrator/evaluator…）是**底层范式**，Anima 的 orchestrator+7 子员工已实现其中几条。
- **Claude Dynamic Workflows** 是**最高形态**：不是用户手搭、也不是固定范式，而是 **Claude 运行时自己编排脚本 + 后台并行 + 自验证**。

**这对 Anima 是决定性利好**：Dynamic Workflows 正是"智能体 × 工作流"的融合终态，而 Anima 手里有两张 Claude 没有的牌——
1. **现成的多 agent 底子**：`orchestrator.py` + 7 子员工 + 受控递归（深度2/预算16）——动态编排的执行层已存在，只缺"运行时自己生成编排"这一层。
2. **可视化画布**：Claude 的动态工作流是**隐形的无头 JS 脚本**（enterprise 开发者面向 terminal）；Anima 可以把它**实时画在画布上**——让用户**看见她自己编排的子 agent 网络在跑**。

**Anthropic 的 5 种工作流模式 + 1 种自主 agent**（权威出处）：
1. **Prompt Chaining**（提示链）：拆成固定顺序步骤，步间设程序化检查点。例：先写文案再翻译。
2. **Routing**（路由）：分类后分流到专门处理。例：客服问题分退款/技术/通用。← **Anima 已有 router 节点**
3. **Parallelization**（并行）：切片并行或多视角投票。例：多模型并行查漏洞。← **Anima 已有 parallel 节点**
4. **Orchestrator-Workers**（编排者-工人）：中央 LLM 动态拆解+委派+综合，子任务**不预定义**。例：跨多文件改代码。← **Anima 的 orchestrator + 7 子员工正是这个**
5. **Evaluator-Optimizer**（评估-优化）：一个生成、一个评审，循环精炼。例：文学翻译反复打磨。← **Anima 有 critic 子员工，但没接成循环**
- **自主 agent**：开放式问题、步数不可预测、靠环境反馈迭代 + 人工检查点。
- **三原则**：**简单（simplicity）· 透明（transparency，展示规划与推理）· 工具文档与测试（ACI，agent-computer interface）**。

**Anima 对照**：可视化引擎是**领先 Codex/Claude Code 的差异化资产**（它俩都没有给非开发者用的可视化工作流画布！）；多 agent 执行层也已就绪；但缺**"运行时动态编排"那一层**（Claude Dynamic Workflows 的核心），也缺 plan mode/todo 驱动/evaluator 闭环。
**取舍（已拍板：C 融合）**：可视化画布保留并强化（护城河延伸）+ 补一层"**Anima 自己把一句话目标动态编排成子 agent 网络、后台并行跑、自验证再汇报**"——但把 Claude 隐形的 JS 脚本**画到画布上**，且**跑在本地**、**有人格**。规模上量力而行（受现有深度2/预算16 护栏约束，几十级而非上百级并行——本地中国模型 + 学生算力跑不了 1000 并行，也不需要）。

### 支柱④ 设计 —— 对标 Claude Design（双重含义）

**含义 A：Anthropic 的品牌/设计语言**（Geist 工作室操刀）
- 字体：**Styrene**（Commercial Type，无衬线，技术理性）+ **Tiempos**（Klim，衬线，人文温度）。
- 配色：暖**橙锈** `#C15F3C`（"Crail"）主色 + 米白/浅灰中性，**刻意不用深蓝**——避免"冷酷未来机器"感，传递平静、可信、温暖。
- 图标：抽象星芒（ideas radiating outward），不张扬但自信。
- 原则：understated（克制）、accessible（亲和）、warm（温暖）。

**含义 B：「Claude Design」工具**（Anthropic Labs，Opus 4.7 视觉）
- 对话式生成设计稿/原型/PPT/一页纸；**读代码库与设计文件，自动套用组织的色彩/字体/组件**；滑杆微调间距/色彩/布局；导出 Canva/PDF/PPTX/HTML；**打包交接给 Claude Code 开发**。
- 哲学：**探索性 + 普惠性**——设计师无约束试多方向，非设计师也能产出专业视觉；靠"自动套用品牌系统"保证一致性。

**Anima 对照**：有暖色 token（`#F7F3EA` 米色底，和 Claude 暖感同源！）+ 人格色，但**没有成文设计体系**——3941 行 CSS 挤在单文件、组件无清单、无设计原则、无字体策略。**这是四支柱里最大的空白。**
**取舍**：v1.2.0 先做**含义 A**（自成一套 `Anima Design`：原则+token+组件，详见 `anima-design-system.md`）；**含义 B**（对话式生成设计）作为远期愿景记一笔——但其实 Anima 的"她能帮你做事"叙事天然适合长出这能力。

## 三、三个战略岔路口（✅ 已拍板 2026-06-07）

> **决策记录**：
> - **#1 工作流 → C 融合**：画布保留强化 + 补"运行时动态编排"层（对标 Claude Dynamic Workflows），把隐形脚本画到画布、跑本地、有人格。
> - **#2 设计体系 → B 全面重设计**：不止 token 化，重做组件库+视觉语言+重写 CSS。**风险最高，故采用"分区域交付的全面重设计"去险**（见 design-system.md 落地路线）。
> - **#3 优先级 → 认同推荐排序**：②MCP内核 → ④设计 → ①异步流式 → ③工作流。

### 岔路口 #1 —— 工作流走哪条路？

| 方案 | 含义 | 优 | 劣 |
|---|---|---|---|
| A 深耕可视化 | 继续做 n8n/扣子方向，强化画布/模板/市场 | 差异化、非开发者友好、已有底子 | 和"智能体生产力"叙事略偏；维护重 |
| B 转向智能体原语 | 弱化画布，主推 plan mode + todo + 自主编排 | 直接对标 Claude，叙事统一 | 浪费已投入的 74KB 画布；丢非开发者用户 |
| **C 融合（建议）** | 画布保留+智能体原语补齐，两种模式互通 | 既守差异化又补对标；"她会自己规划，你也能手搭" | 工程量最大，需想清两层如何互通 |

**我的建议：C。** 具体做法：把 Anthropic 5 模式映射到现有画布节点（routing→router、parallel→parallel、orchestrator→子员工、**evaluator-optimizer→新增"评审循环"节点**），同时新增"**让 Anima 自动把一句话目标编成一张工作流图**"（自然语言→DAG，复用已有节点类型）——这正是可视化画布与智能体的融合点，也是对标方都做不到的。

### 岔路口 #2 —— 设计体系投入多深？

| 方案 | 含义 | 适合 |
|---|---|---|
| A token-first（建议起步） | 先抽 design token + 拆分 CSS + 立原则文档，不重画 UI | 低风险、马上能用、为后续铺路 |
| B 全面重设计 | 重做组件库 + 视觉语言 + 重写 3941 行 | 效果最炸但风险/工期最大 |
| C 不做 | 维持现状 | ❌ 不推荐——"灵魂"没法被感知 |

**我的建议：A 起步，B 分期。** 先 token 化 + 原则成文（`anima-design-system.md` 已起草），随后每个 v1.2.x 迭代重构一个区域（聊天区→工作流区→设置区）。

### 岔路口 #3 —— 四支柱的优先级与排期？

资源有限（本机手动发版、无 CI 额度、单人为主），不可能四线齐开。我的推荐排序：

1. **支柱②（MCP 内核）先行** —— 最大杠杆、是支柱①③的技术前置（异步 `_execute_tool`）。
2. **支柱④ token-first 并行插入** —— 低风险、独立于后端、能立刻提升每次发版的"质感"。
3. **支柱①（本地异步 + 流式）** —— 紧随 MCP，"看着她写代码/提交走人"是高感知爽点。
4. **支柱③（工作流融合）** —— 依赖①的异步与②的工具，放在后面。

## 四、多角色评估

### 🛠 开发视角（可行性 / 风险 / 工程经济）
- **最大风险点**：内核 1（`_execute_tool` 异步化）是 MCP/确认/异步的共同前置，一旦破坏向后兼容会波及 194 个测试。**对策**：`iscoroutine` 守卫 + 单一调用点 + 新回归测试三重兜底（方案已定）。
- **跨线程异步桥**（子员工独立 loop ↔ MCP 主循环 session）是全案最硬的一块，死锁风险真实存在——必须按 `v1.2.0-design.md` 4.3④ 的"看场合分发器"实现，不能图省事全用 `run_coroutine_threadsafe`。
- **设计体系重构**别一次性重写 3941 行——token 化是可增量、可回滚的安全路径。
- **工程经济**：四支柱共用一套内核改动（异步咽喉 + WS 往返），"一次投入解锁多功能"是真实的——别把它们当四个独立项目估工。
- **测试纪律**：`test_single_key`/`test_orchestrator`/`test_persona`/`test_git_safety` 是回归哨兵，每里程碑配独立新测试文件。

### 📊 产品经理视角（定位 / 优先级 / 度量 / GTM）
- **定位句**：Anima = **Claude Code 的能力 + Replika 的灵魂 + 中国模型原生 + 本地优先**。目标用户=用不了 Codex/Claude Code 的中国学生/年轻人。这句话要贯穿四支柱，**任何稀释护城河（灵魂/隐私/记忆）的对标都要否决**。
- **优先级原则**："高感知 × 低成本"先做——**流式 token（看着她写）** 和 **设计 token 化（每次发版都更精致）** 都属此类，应提前。
- **北极星指标建议**：周活中"**完成 ≥1 个真实任务**"的占比（区别于纯聊天）；次级：异步任务完成数、MCP server 接入数、工作流运行成功率。
- **差异化叙事**：对标方都没有的三样——①可视化工作流给非开发者；②有灵魂/记忆的连续关系；③数据不出机器。GTM 主打这三点，而非"我也能写代码"（那是红海）。
- **风险**："什么都对标"= 什么都不突出。建议每个版本对外只讲 1 个主打爽点（v1.2.0 = "看着她写代码 + 提交走人，全程本地"）。

### 👤 用户视角（JTBD / 摩擦 / 惊喜）
- **要做的事（JTBD）**：用户不是来"配置 MCP server"的，是来"帮我把这个 bug 修了/把这批文件改了/把这事自动跑起来"的。所有对标功能都要包进**自然语言入口**，技术配置藏进高级设置。
- **摩擦点**：
  - 当前 onboarding 已优化（名片化），但**首个"她真的帮我干成一件事"的时刻**还没被设计成仪式——这是留存关键。
  - 工作流画布对非技术用户仍有门槛 → 岔路口#1 的"一句话生成工作流"能直接降摩擦。
  - 权限确认（M14）若做成每步都弹窗会很烦 → 必须有"本次会话允许/永久允许"的合理默认。
- **惊喜点（该刻意设计）**：流式"看着她思考+写代码"的过程感；任务完成的桌面通知 + 人格化措辞；设计上的人格色呼吸动效——这些是 Codex/Claude Code **冷工具感**给不了的。

## 六、护城河（任何对标都不能稀释）

1. **灵魂**：一个有性别认知、有情绪、可依靠的"她"——不是工具。设计/措辞/动效都要服务这一点。
2. **记忆**：自动沉淀 + 语言图谱，跨会话连续关系。Codex 无状态、Claude Code 靠手写 CLAUDE.md——这是 Anima 结构性优势。
3. **命理/经济/人格能力**：独有的能力积木，对标方完全没有。
4. **本地隐私**：数据不出机器。这是否决"云端沙箱"的根本理由，也是 GTM 核心卖点。
5. **中国模型原生**：DeepSeek/Qwen/Kimi/GLM——目标用户用不了 OpenAI/Anthropic 的结构性必然。
